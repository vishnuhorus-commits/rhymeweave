HORUS SOLAR FUNNEL — START HERE

Open this page in Microsoft Edge or Google Chrome on your Windows computer:
https://vishnuhorus-commits.github.io/rhymeweave/horus-command-center.html

1. Paste writing into the Solar Funnel, or choose ADD FILES / ZIP or ADD FOLDER.
2. Choose CHOOSE YOUR A–Z FOLDER. Select D:\HORUS_AZ_FILE_FOUNDATION in the Windows folder picker. The browser cannot connect to D: just because a path is printed on a page.
3. Choose SEPARATE & FILE. This creates NEW copies in real A–Z and PHONETIC_FAMILIES folders. Existing files are never replaced, merged, renamed, moved, or deleted. Your H: backup is not changed.
4. Choose BROWSE SAVED FOLDERS to read the actual saved files. For clickable local file/directory links, open the per-run INDEX.html from inside the saved HORUS_FUNNEL_RUNS batch folder.

If you do not want to connect a folder, choose DOWNLOAD FOLDER ZIP instead. The ZIP contains the same kind of A–Z/family text files, originals, source references, review reports, and a linked index. Extract the entire ZIP together so its relative links work.

HOW YOUR WRITING IS KEPT SAFE

The browser archive and its existing Command Desk controls are unchanged. Solar Funnel does not require finished writing to pass the old three-word alliteration gate. Each nonblank line remains intact in the A–Z export, with its original case and punctuation. Letter sorting uses the first alphabetic letter, including common Latin-letter transliteration; other scripts remain under an underscore bucket when no Latin letter is available.

Family views use the existing Command Center's starting-sound/consonant-skeleton approximation. A line may appear under more than one relevant family. These are suggestions, not a pronunciation dictionary or a promise that every word sounds alike. Unknown/unclassified text stays in A–Z and is noted in Review. Duplicate occurrences within a batch are recorded in Review and provenance; original source files remain intact. Repeating a whole export creates another uniquely named batch rather than changing a previous batch.

Recognized chunker ZIPs with A_Z/A.txt or A-Z/A/... files use those primary writing buckets. Their root logs, README files, and secondary indexes are not re-imported as writing. Bucket headings are noted rather than treated as writing. The complete original ZIP is retained.

Plain text, Markdown, CSV/JSON text, HTML text extraction, and DOCX paragraphs are supported. HTML/script input is not executed. PDF/scanned pages, RTF, and other unsupported formats are reported, not guessed; original inputs remain untouched. Password-protected/malformed ZIPs stop with an error. Nested ZIPs are not recursively expanded.

For manageable batches, each input file is limited to 32 MiB; queued inputs total up to 96 MiB; expanded data up to 128 MiB; 200,000 line records; and generated outputs up to 220 MiB. Text outputs split into chunks of up to 5,000 writing lines. If a batch exceeds these limits, use smaller chunker files/ZIPs. No output is silently truncated.

This is a button-operated local funnel, not an unattended folder watcher. It does not automatically upload writing or update the H: backup. Your browser controls folder permissions, and you may need to reconnect the destination after reopening the page or clearing browser permissions.
